# 決策（ADR）

**知識狀態：** 權威 · **負責人：** 決策者 · **ID 前綴：** `ADR` · **範本：** [`templates/adr.md`](../../templates/adr.md)

> **每個重要的技術決策都應該有可追溯的理由。**

## 什麼時候寫 ADR

- 你在真實存在的替代方案之間做了選擇，而且落選的方案也是合理的。
- 這個決策很難回頭（資料模型、供應商、框架、演算法策略）。
- 未來的同事——或 AI——否則可能會「修正」某個其實是刻意為之的東西。

## 什麼時候不用寫

- 沒有真正替代方案的選擇、風格偏好，或既有 ADR 已經涵蓋的事。

## 規則

- ADR **一旦被接受就不可變更**，只能改狀態、連結，以及追加備註。要改變決策，就寫一份新的 ADR `supersedes` 舊的；舊的設為 `deprecated`。
- **AI 絕不刪除或改寫已接受的 ADR。** 它可以起草一份取代用的 ADR 作為提案。
- 以某條商業規則為前提的 ADR 應連結到該規則（`decides_for: BR-…`），這樣規則改變時就會標記這份 ADR 需要重新審查。
