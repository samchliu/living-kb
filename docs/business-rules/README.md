# 商業規則（Business Rules）

**知識狀態：** 權威 · **負責人：** PM · **ID 前綴：** `BR` · **範本：** [`templates/business-rule.md`](../../templates/business-rule.md)

商業規則是關於業務、且無論如何實作都**必須保持為真**的陳述：門檻、上限、資格條件、計算方式、排序。

> 「每間門市每天最多顯示 5 則推薦。」
> 「銷售歷史少於 14 天的商品永遠不會被推薦。」

## 規則

- **BR 一旦核准，就是該規則的事實來源**——高於程式碼、高於原型、高於某人記得老闆說過的話。如果程式碼與之不符，那就是**偏移（drift）**，要回報，而不是默默接受。
- 一份 BR 文件可以包含數條密切相關、有編號的規則（`BR-001 R1…R6`）。引用時寫成 `BR-001#R3`。
- 每條規則都要有**理由**。如果沒人知道規則為什麼存在，就寫「未知——沿用自 <來源>」，讓健康 Agent 追蹤。
- 可調整的數值放在**參數**表中。改參數仍然是規則變更——記錄在變更歷史中。
- 每條規則都應該至少被一個測試 `verified_by`。未被測試的規則會被回報為 `MISSING`。
- AI 可以提議從需求或回饋中抽出的規則。**只有 PM 能核准。** AI 絕不能僅從程式碼行為推論出規則。
