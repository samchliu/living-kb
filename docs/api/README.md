# API 與資料合約

**知識狀態：** 權威 · **負責人：** RD · **ID 前綴：** `API` · **範本：** [`templates/api.md`](../../templates/api.md)

前後端之間、服務之間，或與外部合作夥伴之間的合約——以及這些合約所暴露的資料結構。

## 規則

- 如果存在機器可讀的規格（OpenAPI、GraphQL schema、protobuf），**它**就是資料結構的事實來源；`API` 文件說明目的、商業規則、錯誤與效能預期，並設定 `source_of_truth: <規格路徑>`。
- 每個執行商業規則的端點都要連到該規則（`implements: BR-…`）。
- 對已核准合約的破壞性變更需要 RD 核准；若使用者可見，還需 PM 審查。記錄在變更歷史中。
- 沒有透過 API 暴露的資料結構（資料表、事件）也可以用同一個範本記錄在這裡，規模小的話也可以寫在 ARCH 文件中。
